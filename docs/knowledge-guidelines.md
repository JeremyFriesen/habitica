# Knowledge & Documentation Guidelines

## ✅ Keep knowledge inside the project

All project-specific knowledge, tips, and workflow explanations should live inside the repository itself (under `docs/`, `README.md`, or similar), so anyone cloning the repo can discover it without external tools.

## ✅ Link to new docs

Whenever you add a new documentation file (e.g., `docs/local-dev-hot-reload.md`):

- Add a reference to it from a well-known entry point (e.g., `README.md`, `CONTRIBUTING.md`, or an existing docs index).
- If the repo has a `docs/` landing page or table of contents, add it there.

This ensures the knowledge is discoverable and stays connected to the project.
